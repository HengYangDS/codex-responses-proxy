## Why

Proxy already has a `VERSION` carrier and Python-native quality graph, but its accepted `dev` train is not locally converged into `main`, and its release installation contract exposes shell-variable grammar in a machine-oriented governance surface. The repository needs one concise portable contract without another runtime or compatibility layer.

## What Changes

- **BREAKING** Make `VERSION` the sole release identity and remove competing inferred paths.
- Make local `dev` to `main` closeout explicit and ETHOS-governed.
- Refine release/install contract so product UX is executable-first and repository DX is manifest-driven and portable.
- Align editor, quality, docs, OpenSpec, and evidence navigation without parallel authorities.
- Preserve provider-portable replay, store=false, recovery, backpressure, native supervision, and independent Forge boundaries.

## Capabilities

### New Capabilities

- `repository-organization`: one portable contract for version, branch lifecycle, quality entry points, and documentation ownership.

### Modified Capabilities

- `product-interface`: repository DX and installed product UX remain separate while sharing one explicit release contract.

## Impact

Affects release metadata validation, repository docs, OpenSpec, quality declarations, and ETHOS proof inputs. Does not alter Codex session data, client config, credentials, or proxy wire protocol.
