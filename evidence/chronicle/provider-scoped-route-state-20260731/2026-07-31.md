# Provider-scoped route-state evidence

Date: 2026-07-31

## Incident

At `2026-07-30T21:33:58Z`, the installed v1.0.43 runtime was running with one
verified listener (PID 36767), no payload transaction, AIGW route authority,
and `route=drifted`. Its proxy-owned `install-state.json` was schema v2 and
recorded account `dmxapi` with `proxy_url=http://127.0.0.1:8791/v1`.

The canonical AIGW endpoints were already provider-scoped:

```text
dmxapi   -> http://127.0.0.1:8791/dmxapi/v1
ucloud   -> http://127.0.0.1:8791/ucloud/v1
aihubmix -> http://127.0.0.1:8791/aihubmix/v1
```

UCloud retained `codex_responses_storage = "required"`. No credential or
session content was retained in this evidence. The defect was therefore in the
proxy route-state model and installed control, not in listener routing or the
canonical AIGW projection.

## TDD and source repair

Focused RED execution against unchanged production behavior proved four
independent gaps:

- the explicit legacy and provider-scoped URL constructors did not exist;
- `adopt_aigw_route` accepted no provider route and rejected the canonical
  scoped endpoint;
- scoped state at a non-default listener port fell back to port 8791; and
- newly written direct state still used schema v2.

Additional RED cases proved that a credentialed loopback URL and explicit port
zero were incorrectly accepted for port discovery, that `adopt-aigw` could
attempt a two-owner legacy endpoint migration, and that schema-v2 enable could
reintroduce an AIGW route without first minting schema-v3 state.

The source repair now has one bounded contract:

- newly written route state uses schema v3;
- direct `codex_config` state keeps the bounded unscoped `/v1` route and exact
  hash-bound restoration behavior;
- AIGW state records an explicit `dmxapi`, `ucloud`, or `aihubmix`
  `provider_route` and the matching scoped loopback URL;
- schema-v1/v2 direct state and schema-v2 AIGW state remain readable, but
  schema-v2 AIGW state cannot enable `/v1`;
- AIGW must first project either the exact direct endpoint or exact scoped
  endpoint through its public lifecycle, after which `adopt-aigw` atomically
  replaces only proxy-owned state;
- installed control parses only credential-free HTTP loopback URLs with a
  supported path and valid explicit port.
