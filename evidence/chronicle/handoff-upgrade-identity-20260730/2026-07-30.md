# Handoff upgrade identity evidence

The live `1.0.35 -> 1.0.36` installation committed the exact `1.0.36` payload,
then the old listener returned HTTP 409 because its successor-disk check used
the old process's frozen `1.0.35` identity. The old listener remained accepting
and the transaction was retained as `recovery_required`; no forced termination
or direct journal edit was used.

The local `1.0.37` candidate now separates the old process identity from the
complete committed successor identity. It also provides two explicit recovery
steps: restore an exact retained rollback only when the live idle listener is
the sole PID bound to the installed entrypoint and matches the rollback release,
serving digest, receipt digest, and manifest digest; then replace that listener
only under the separate `--force-v2-bootstrap` authorization, with prior-runtime
rollback proof on failure.
