# Post-release main validation evidence

Date: 2026-07-31

## Incident

GitLab main pipeline 3959 passed the Python 3.12, 3.13, and 3.14 jobs but
failed `verify-release-metadata`. The job selected `--prepare-release` for every
untagged commit even though `VERSION` remained `1.0.45` after the signed
`v1.0.45` release already existed. The checker correctly rejected that state:
`release tag v1.0.45 already exists; use --tag validation instead`.

## Contract and repair

The release-contract test was changed first. Against the unchanged CI
projection it failed only because the published-main branch was absent. The
GitLab projection now selects one of the checker's existing modes:

1. an exact tag pipeline validates `CI_COMMIT_TAG`;
2. an untagged commit whose exact `refs/tags/v$(cat VERSION)` exists performs
   ordinary GitLab provider validation; and
3. an untagged commit without that tag prepares the pending release.

The job already fetches the complete provider tag namespace with forced tag
pruning before this dispatch. No checker wrapper, version change, tag rewrite,
or runtime behavior was added.

## Local verification

- The focused release metadata, Markdown, quality-contract, GitLab/GitHub
  provider projection, publish/tagging, and strict OpenSpec gates passed.
- Python 3.12, 3.13, and 3.14 each passed 440 tests.
- The Python 3.12 canonical quality gate passed Ruff 0.16.0, ty 0.0.64,
  structure, formatting, 5,102 statements at 96.94%, and 1,684 of 1,768
  branches at 95.25%.
- Captured focused and heavy-gate logs contained no real Python traceback,
  warning, ignored exception, socketserver exception banner, pip root warning,
  or Debian frontend warning.

## Boundary

This record proves only the local source contract and verification. Signed
commit identity, exact-HEAD ETHOS proof, candidate landing, dual-Forge main CI,
release-asset continuity, installed runtime observation, repository-family
record creation, and Work Lane retirement remain separate external transitions
until fresh evidence proves them.

No Codex JSONL, SQLite state, conversation history, archive, or model metadata
is read as a mutation target or changed by this repair.
