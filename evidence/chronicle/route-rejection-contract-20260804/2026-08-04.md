# route-rejection-contract — 2026-08-04

- 2026-08-04: Root cause, measured on the wire rather than inferred.
  `Handler.protocol_version = "HTTP/1.1"` (`listener/server.py:99`) makes every
  connection persistent by default, and `BaseHTTPRequestHandler` decides
  reusability from the `Connection` header it observes on the way out. Three
  paths answer without consuming the request body: the closed-route and
  unsupported-method rejections in `transport/responses._reject_route`, and
  `listener/control.set_drain`, which carries its lease in a header and never
  reads a body. None declared the connection closed. Sending one rejected
  `POST /unknown/v1/responses` with a JSON body followed by
  `GET /healthz` on the same socket produced two status lines: the intended
  `404` and a spurious `400 Bad request syntax`, synthesized by the listener
  parsing the caller's own JSON as the next request line. The client's real
  second request was consumed and never answered.
- 2026-08-04: TDD, RED observed on all three sites as `AssertionError: 2 != 1`
  against `wire.count(b"HTTP/1.1 ")` in
  `tests/providers/test_routes.py::test_a_rejected_route_never_answers_twice_from_its_unread_body`
  and
  `tests/transport/test_proxy.py::test_a_drain_toggle_never_answers_twice_from_its_unread_body`.
  The tests speak raw bytes through a new `raw_exchange` fixture helper rather
  than an HTTP client, because a client library hides exactly the framing under
  test. GREEN followed on the single decision: declare `Connection: close` on a
  response emitted before its body is read.
- 2026-08-04: The converse guard,
  `test_a_locally_answered_request_whose_body_was_read_stays_reusable`, passed
  on first run, which is not a RED and therefore not yet evidence. It was proved
  non-vacuous by mutation: setting `close: bool = True` as the default in
  `transport/relay.send_payload` produced `FAILED (failures=1)`; the file was
  then restored and the default re-verified as `close: bool = False`.
- 2026-08-04: Draining the unread body was considered and rejected. The length
  is caller-controlled, so draining spends real bandwidth on a request already
  refused; a chunked request body cannot be skipped by length at all, and this
  listener does not decode chunked requests; and it reads bytes the listener has
  already declined to accept. Closing is bounded, framing-independent, and costs
  one reconnection on a path that had already failed.
- 2026-08-04: `GET /healthz` deliberately keeps the reusable default. It
  consumes no body, is polled repeatedly by supervision, and closing it would
  charge a connection per probe for no framing benefit.
- 2026-08-04: The specification contradiction was duplicated ownership, not
  wording. `openspec/specs/provider-portable-responses/spec.md:148` admits both
  `POST /<provider>/v1/responses` and `GET /<provider>/v1/models`; the
  admission requirement at `:350` restated the routing rule as
  `/v1/responses`-only, and its scenario rejected "a non-Responses endpoint",
  which the admitted catalog route falsifies. The duplicate was correct when
  Responses was the only route and was left behind when the catalog route
  landed. `openspec validate --strict` cannot detect this: it validates
  structure, not agreement between requirements. The fix removes the duplicate
  rather than correcting it, so the next admitted path cannot recreate the
  contradiction; "lexically normalized" was carried onto the surviving sentence
  so the dedupe drops no meaning, and the ambiguous-suffix scenario moved with
  its stale clause replaced by "a method the matched target does not admit". No
  prose linter was added: the real behavior is already pinned by
  `tests/providers/test_routes.py`, and the drift happened precisely because the
  rule was stated twice.
