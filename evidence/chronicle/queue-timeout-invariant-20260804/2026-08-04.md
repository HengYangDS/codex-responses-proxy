# queue-timeout-invariant — 2026-08-04

- 2026-08-04: The live listener (release 2.0.7, pid 10903, uptime 96199 s)
  reported `responses_received: 6391`, `responses_completed: 5581`, and
  `responses_local_queue_timeouts: 652`. The denial path had therefore fired on
  10.2 percent of received requests, which is the reported `gpt-5.6` symptom
  `local proxy overloaded: timed out waiting for responses concurrency slot (8)`
  measured rather than inferred.
- 2026-08-04: A census of the four rotated proxy logs recovered 18364 route
  holds (ucloud 16375, dmxapi 1981, aihubmix 8) and 656 queue-timeout denials,
  652 of which matched the hold that blocked them; 4 were unmatched. For each
  match the wait the request actually needed was reconstructed as
  `hold_end - (T - 120)`: min 121 s, median 144 s, max 917 s. The old 120-second
  default sat immediately below the median, so it was denying the requests that
  were about to succeed. Cumulative admission by candidate wait: 150 s 55.4%,
  180 s 64.9%, 240 s 77.6%, 300 s 82.4%, 360 s 86.5%, 480 s 91.0%, 600 s 94.0%,
  900 s 99.5%, 1200 s 100%.
- 2026-08-04: The value was derived, not picked. A waiter must not be denied
  while the holder ahead of it is still inside its own total deadline, and that
  deadline is `DEFAULT_UPSTREAM_TIMEOUT`. `DEFAULT_RESPONSES_QUEUE_TIMEOUT =
  DEFAULT_UPSTREAM_TIMEOUT` states the relationship structurally; the census is
  corroboration. 900 also lies inside the pre-existing validated bound
  `0.001..3600`, so the operator surface is untouched.
- 2026-08-04: Correction to `route-slot-lease`. That change recorded that
  raising the released default would reach no installed operator, and that
  delivering it would need `install --force-v2-bootstrap` — "the same operator
  act as setting the variable". Tracing the full chain shows the opposite.
  `commands/install.py` argparse exposes `--port`, four log-retention flags,
  `--trust-anchor`, `--timeout-seconds`, and four bootstrap-mode flags, and no
  queue-timeout flag; `commands/install.build_context` accepts no such
  parameter; `runtime_context.create` accepts no such parameter. Therefore
  `RuntimeContext.responses_queue_timeout` can only ever hold
  `config.DEFAULT_RESPONSES_QUEUE_TIMEOUT`, and
  `RuntimeContext.service_environment` (`runtime/context.py:50`) renders exactly
  that into the unit. The code default is not one lever among several — it is
  the only lever a supervised install has, and an install does deliver it. The
  archived chronicle and the claim's `[carriers].fallback` are corrected in
  place today.
- 2026-08-04: TDD. The RED was observed as `AssertionError: 120.0 not greater
  than or equal to 900.0` from
  `tests/runtime/test_admission.py::test_default_queue_wait_is_not_shorter_than_one_upstream_deadline`.
  The contract asserts the invariant, not the literal, so a later upstream
  retune stays legal. GREEN followed on the one-line derivation; full quality
  returned rc=0 with `TOTAL 5674 155 1746 87 96.74%` and
  `{"covered_branches": 1659, "covered_lines": 5519, "gaps": [], "ok": true}`,
  byte-identical to the pre-change baseline.
- 2026-08-04: Not yet true at commit time. The running listener still pins
  `CODEX_RESPONSES_PROXY_RESPONSES_QUEUE_TIMEOUT=120.0` in
  `~/Library/LaunchAgents/codex-responses-proxy.watchdog.plist`. Until a
  reinstall re-renders that unit, no live request observes this change, and the
  live denial counter remains the acceptance evidence.
- 2026-08-04: Acceptance, measured. Release 2.0.8 was installed and the unit
  re-rendered to `CODEX_RESPONSES_PROXY_RESPONSES_QUEUE_TIMEOUT=900.0`, which
  confirms the corrected chain above: the code default is what a supervised
  install delivers. After 6393 seconds of live traffic the listener reported
  `responses_received: 220`, `responses_completed: 212`, and
  `responses_local_queue_timeouts: 0`. The 2.0.7 baseline over the same counter
  was 652 denials on 6391 received requests, a 10.2 percent denial rate. The
  reported `gpt-5.6` symptom `local proxy overloaded: timed out waiting for
  responses concurrency slot (8)` has therefore not recurred once since the
  change reached a live listener, and no legitimate long turn was truncated by
  the total-deadline bound over that window. This entry closes the acceptance
  that the entry above left open.
